# 社区讨论怎样安排

[community Discussions](https://github.com/OpenRDHub/community/discussions) 已启用，随仓库保持私有。组织级 Discussions 尚未配置，不能把仓库讨论区当作已开放的组织公共入口。

| GitHub 分类 | 用来讨论什么 | 何时转入任务 |
|---|---|---|
| [Q&A](https://github.com/OpenRDHub/community/discussions/categories/q-a) | 参与方法、资料位置、遇到的困难 | 说明需要修改时关联原 Issue |
| [General](https://github.com/OpenRDHub/community/discussions/categories/general) | 实际做法、参考资料、复盘 | 需要沉淀为文档时建立编辑任务 |
| [Ideas](https://github.com/OpenRDHub/community/discussions/categories/ideas) | 参与规则、分工和公共协作提议 | 范围与责任清楚后建立执行事项 |
| [Announcements](https://github.com/OpenRDHub/community/discussions/categories/announcements) | 已确认的决定、实际成果 | 直接链接原任务和文档 |

保留 GitHub 默认的 Polls、Show and tell 分类，按需要使用，不预设活动或内容数量。

## 当前讨论

[社区协作试行：任务接待、资料收录与公开入口](https://github.com/OpenRDHub/community/discussions/9)。这里征求分工和公开范围的意见；六个执行事项的进展分别回到原 Issue。

## 讨论约定

标题说清问题，正文提供必要背景。讨论不同方案时说明影响；不需要公开个人经历或身份来证明观点。

需要决定的议题由实际承担者确认负责人和讨论时间。结论回到原议题，稳定规则再用 PR 修改。问答和提议不代表已经承诺实施。
