# 公共讨论怎样安排

拟将社区讨论集中在 community。下面是分类草案，尚未在 GitHub 创建。

| 分类 | 用来讨论什么 | 何时转入任务 |
|---|---|---|
| 问答与新人交流 | 参与方法、资料位置、遇到的困难 | 发现需要修改的说明时关联社区事项 |
| 经验与资料 | 实际做法、参考资料、复盘 | 需要整理为稳定文档时认领编辑任务 |
| 社区提议 | 参与规则、工作安排、公共协作建议 | 范围与责任清楚后建立执行事项 |
| 公告与进展 | 已确认的决定、实际成果与后续安排 | 直接链接原任务和文档 |

## 讨论约定

标题说清问题，正文提供必要背景。讨论不同方案时说明影响；不需要公开个人经历或身份来证明观点。

需要决定的议题写清负责人和讨论截止日，并通知受影响的人。结论回到原议题，稳定规则再用 PR 修改。

问答和提议不是已经承诺实施的任务。已有执行事项时直接链接，避免两处重复跟进。
