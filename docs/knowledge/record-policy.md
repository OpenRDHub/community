# 收录与维护约定

**拟议约定，待社区讨论。**

## 保留过程，不制造共识

会议纪要和微信群讨论可以在未达成结论时入库。正文分别写清“讨论过什么”“已确认什么”“尚未决定什么”。整理者的推测不能写成他人的承诺。

草稿、待复核、已复核、已替代是记录状态；提案是否通过是另外一回事。决定记录必须有确认依据与日期，否则仍是提案。合并归档 PR 不等于通过提案。

## 一条记录应带什么

| 字段 | 约定 |
|---|---|
| ID | 固定标识，首次建立后不变，便于关联和去重 |
| 类型 | 会议、讨论、决定、每日资料、方案或参考资料 |
| 日期 | 分别保存发生日期和最后修订日期 |
| 来源 | 飞书原文及修订版本，或微信群代称、讨论日期范围与整理稿版本；无可分享链接时写来源描述与联系角色；只保留适合当前受众的信息 |
| 主版本 | 飞书或 GitHub，更新须回到这个主版本 |
| 整理与复核 | 记录实际参与者；未落实就写待确认，不自动指派 |
| 内容状态 | 草稿 / 待复核 / 已复核 / 已替代 |
| 公开范围 | 内部 / 可公开；未标注按内部处理 |
| 发布 | 是否已明确允许进入公开网页；记录状态与公开范围分别核对 |
| 关联 | 相关讨论、决定、资料、PR 和待办 Issue |

## 常见情况

- 同一飞书文档有新版本：更新原记录、来源版本与变更说明，不复制一个“最终版2”。
- 同一个微信群主题讨论持续几天：追加新的观点和日期；只有出现独立新议题才拆记录。
- 会议产生三个待办：建三个可执行事项，纪要引用它们；不在纪要里维护第二份进度。
- 决定被修改：新建替代决定，旧记录标记“已替代”，双向链接，保留当时的理由。
- 新资料只有飞书链接：标记“仅登记来源，未完成归档”；不能在网页显示“已同步”。
- 图片或附件仍需登录：保留访问说明。只有得到许可且完成复制核验，才标记归档完成。
- 需要撤回公开内容：停止公开构建、移除公开产物与下载副本，再处理仓库历史和外部缓存；删除当前文件不等于删除历史。

- 微信讨论没有可分享的原文链接：记录群代称、日期范围和联系角色，必要摘录或截图留在受限位置供核对，不编造链接。
- 微信整理稿经核对后：把摘要链接和未决问题回贴原群；后续补充仍更新同一记录。

## 如何提交

不会使用 Git 的贡献者可以把整理稿交给资料接待人；会使用 Git 的贡献者按模板发 PR。接待人帮助落库，但署名仍归实际贡献者。每周整理一份“新增、更新、待确认”的短摘要，引用原记录。

模板、示例与流程已收录在私有 community 仓库，规则仍待社区复核；尚未建立真实资料导入队列、自动同步任务或指定资料接待人。

## 模板收录与校验

复制模板到 records/ 后填写 YAML，替换 REPLACE-ME 并更新日期、来源版本。缺字段或非法值会报错，模板目录不被索引。单语言记录在另一界面显示原文语言提示。

`status`: draft / pending-review / reviewed / superseded; `authority`: github / feishu; `visibility`: internal / public / restricted; `publication`: pending / approved / published.

可选 source_url、authority_url 必须是适合受众的 http(s) 原文链接；publication 只是元信息，不是发布操作。
