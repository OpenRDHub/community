# Everyday collaboration

## A community task

Describe the problem → define the outcome and references → confirm support and review → take the task → submit → receive feedback → continue, hand over, or finish.

Each task has one primary issue. Suggested states are Needs confirmation, Ready to take, In progress, Awaiting feedback, Done, and On hold. A board references the original item rather than duplicating it.

Agree on a check-in when taking a task, and adjust scope, timing, or handover arrangements when needed. Link the result and review feedback when finishing.

## Keeping information accessible

Use chat for conversation. When a task, decision, or reusable lesson needs follow-up, the responsible person writes a brief summary back to the original item or document.

Questions can start in Discussions; recurring questions can become an FAQ. File changes go through pull requests. Maintain a decision in one place and link to it elsewhere.

## Proposed maintenance rhythm

| Frequency | Work | Record |
|---|---|---|
| Weekly asynchronous check | New questions, waiting items, tasks, and expiring resources | Update the original items and relevant directories |
| Monthly community update | Actual outcomes, contributions, and gaps | A short update with links |
| Meetings when needed | Cross-role decisions, questions, or sharing | Conclusions and next steps |
| Responsibility changes | Intake coverage, permissions, and handover | Updated maintenance arrangements |

Actual participants must agree to this rhythm. Automated greetings do not replace human intake. If nobody can take over, explain what is needed before work can continue.
