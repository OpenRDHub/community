# Contributing to OpenRD

Start with the [organization profile](https://github.com/OpenRDHub) and choose the destination based on the change.

- Known project bugs or features: use its documented issue tracker and receiving repository.
- OpenRare: the organization repository is a fork; use [upstream Issues](https://github.com/OpenRare2026/OpenRare/issues).
- Needs without a project: the existing entry is [Khub-OpenRD/rare-disease-list](https://github.com/Khub-OpenRD/rare-disease-list/issues), under a personal account. Use existing contacts; no unified response time is promised.
- Community documents: private community content requires access; external contributors can use existing contacts on the organization profile.
- Organization profile and default rules: changes belong in [.github](https://github.com/OpenRDHub/.github), not unrelated project bug reports.

## Sending changes

Small independent fixes may go directly to a PR. Link an existing Issue when applicable; describe source, output and acceptance for larger work. Check the receiving repository and branch. A personal fork is a valid source.

Explain the change, reason, checks and remaining review. Proposal adoption, merging and real-world acceptance are separate steps.

Writing, source checking, usability feedback and resource coordination are welcome. Share material appropriate for the destination's audience.
