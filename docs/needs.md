# 提出一个需求

从真实的使用情境开始：谁遇到了什么困难，现在怎样处理，希望有什么改善。

## 可以先写这些

- 使用场景与当前困难。
- 已有办法，以及仍不方便的地方。
- 希望优先改善的一点。
- 是否已有相关项目或资料；可接受的反馈方式可以后续商定。

不需要先会写技术方案。公开记录只保留适合公开的摘要，不放原始病历、身份资料或私人联系方式。

## 社区收到后

接待人帮助补充情境、查找相似需求。已有项目归属的关联到主仓库；尚未归属的在 community 保留记录。

本轮先完善接待方法。登记需求不表示已经立项或承诺开发日期，可标为待补充、待承接或已关联。

## 后续联系

反馈方式与时间由需求方自愿商定，可以暂停，也可以请认可的联络人协助。接待安排尚待确认，见[维护分工](../MAINTAINERS.md)。
