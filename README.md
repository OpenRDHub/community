# 一起把社区建设好

这里维护 KHub / OpenRD 共同使用的参与说明、协作规则、需求入口和资源目录。

当前重点是社区建设。无论是否写代码，都可以从整理资料、改进说明、测试参与流程或协助接待开始。

## 选择你的第一步

| 你的想法 | 从哪里开始 |
|---|---|
| 我想帮忙，但还不知道做什么 | [参与指南](docs/getting-started.md) |
| 我已经发现一个可以改进的地方 | [贡献方法](CONTRIBUTING.md) |
| 我想提出需求 | [需求登记](docs/needs.md) |
| 我能提供指导、设备、费用或其他支持 | [资源协作](docs/resources.md) |
| 我想了解谁负责、怎样作决定 | [维护分工](MAINTAINERS.md)与[协作规则](GOVERNANCE.md) |

## 先做这些公共工作

我们准备整理首页导航、新人说明、历史资料、常见问题、需求模板和资源信息。这些是首批候选事项，接待与评审安排落实后再开放认领。

[查看建设清单](ROADMAP.md)

## 信息放在哪里

- **文档**：稳定的说明、目录和规则。
- **Issues**：有明确下一步的社区事项、需求和资源登记。
- **Discussions**：问答、经验与开放想法。[查看讨论分类](docs/discussions.md)。
- **PR**：需要审阅的文档、目录和模板修改。
- **项目仓库**：具体项目的实现与交付；这里保留[项目导航](docs/projects.md)。

同一项执行工作只保留一份主要记录，其他入口用链接关联。

## 参与之后

完成的工作得到具体反馈，并按本人意愿记录成果与署名。愿意继续的人可以接下一项工作，也可以逐步承担文档维护、接待或评审职责。

[贡献与成长](MEMBERSHIP.md) · [日常如何协作](docs/working-together.md)

> community 及其 Issues、PR、Discussions、社区看板均已公开；组织 Discussions 与 community 共用同一讨论区。六个事项已登记，尚待确认接待与评审；角色和规则仍待社区讨论，不代表已经指派或通过。
